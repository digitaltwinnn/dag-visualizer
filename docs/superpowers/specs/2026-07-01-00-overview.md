# HUD refresh — overview & cross-cutting invariants

**Date:** 2026-07-01
A single entry point for the Instrument-Glass HUD redesign: the spec index, the **laws that apply everywhere** (so individual specs stay consistent), the build order, and the open/deferred threads. Read this first.

## The invariants (apply across every spec)

1. **Instrument-Glass** — translucent glass panels, mono numerics, a left accent spine; the 3D scene is the star, chrome recedes.
2. **Two colour lanes, never cross.**
   - **Structural** (chrome + status) → shadcn CSS vars + `--success`/`--core-l0`/`--core-l1`.
   - **Identity** (per-metagraph) → the runtime **OKLCH generator** (`--mg-<id>`, brand-matched, guard-banded). Reserved structural bands include **amber ~90° (status "in progress")**.
   - Never a metagraph hue for chrome/status; never a chrome hue to identify a metagraph.
3. **Number-colour rule** — data numbers are **neutral** (headline white/bold, secondary muted). **Cyan = live/accent only** (ECG, spine, active view, live sparkline bar, node-halo, selection). Identity hue only on per-metagraph marks (dot/bar/thread/ticker/pill).
4. **Calm, meaningful motion** — ~1.5 s breathe, **opacity over transform**, low ceilings; motion fires only on **meaningful** change (a tick, a resolve, a status change), never idle. Reduced-motion → static.
5. **Status system** — the ~9-state node lifecycle → **colour = bucket** (green in-consensus / **amber** in-progress / red down / muted unknown), **text = exact state**. Single = text (Ready) or pill; breakdown = bucket counts+dots. Error never breaks a card's identity-hue frame.
6. **Factual, never fabricated** — absence is an honest *reading* (NO SIGNAL / ACQUIRING / STANDBY / gaps), never faked; counts authoritative, visuals may cap/approximate only when a real value is also shown.
7. **Zone roles / IA:**
   - **Top** = command bar (brand+status, filter, view switch, vitals).
   - **Left** = the view's **interactive** panel — data-explore (GeoExplore) or interactive-learning (ledger settlement-stack legend, hyper tour).
   - **Right** = the **subject stack** (Context → Detail, identity-thread) + the **text** view-default explainer.
   - **Bottom** = the LiveStrip.
8. **One focus language across chrome + canvas** — synced glow (no tether), bidirectional hover, click commits (card pins + scene focus + filter). Hover previews, click commits.

## Build order (implementation plan will detail)

1. **Tailwind + shadcn init** + the **token layer** (two lanes, the bridge below) — keep the app shippable.
2. Primitives (Card/Tooltip/Command/ToggleGroup/Avatar/Badge/ScrollArea/Sheet) themed Instrument-Glass + the custom bits (ECG/thread/caps/halo/odometer).
3. Zone by zone: command bar → right-rail stack + cards → left rail + bottom strip → tie-in → states/first-load → responsive.
4. The `/design` styleguide route as the living reference + screenshot check.

## Token bridge into the 3D engine (principle)

Design attributes must not be hardcoded in `js/*`. **Animations (lerp/easing/render loop) stay in the engine; colours + visual attributes (hue, dim, bloom, glow, opacity) resolve from the design system:**
- **Structural** params → a shared TS token module the engine imports (→ `THREE.Color`/numbers), also feeding CSS.
- **Identity** hues → read `--mg-<id>` CSS vars at runtime (`getComputedStyle` → `THREE.Color`), refreshed on metagraph/theme change.
- **Audit** `config.js` (`COLORS`/`VIS`), `scene.js` (bloom), and `layers`/`globe` glow/dim/opacity constants — externalize these.
