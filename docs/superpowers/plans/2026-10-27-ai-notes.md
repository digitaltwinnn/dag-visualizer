# AI Notes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give each 3D view an "AI notes" card. A free Gate AI model writes it from that view's measured facts, a mechanical honesty gate checks it, and Redis caches it. History also gets notable-day diamonds on its timeline.

**Architecture:**
- **Pure facts and checks** live in `src/data/` (rule 4):
  - one facts builder per view
  - the honesty gate
  - notable-day detection
- **Server plumbing** lives in `app/api/notes/`, mirroring `app/api/trends/`. It holds the Gate client, prompts, a narrow Redis store, a generator that orchestrates the steps, three routes (read, request, warm) and an hourly cron warmer.
- **The HUD side** has four parts:
  - a `notes` rail card, wired through `railCards.ts` and `Inspector.tsx`
  - a hook with a module cache
  - a `viewPolicy` opt-in
  - one new hover channel that pairs History's timeline diamonds with the card's "Notable days" rows

**Tech Stack:** Next.js 16 route handlers (Node runtime), TypeScript, `@upstash/redis`, Vitest (`node` env), React + Zustand, lucide-react.

**Spec:** `docs/superpowers/specs/2026-10-27-ai-notes-design.md`. Read it first: every **(user)** decision there is fixed.

## Global Constraints

**Model and secrets**
- The model is `process.env.GATE_MODEL ?? "constellation/qwen3-8-flash-free"`.
- The endpoint is `https://gateway.constellationgate.ai/v1/chat/completions`, OpenAI shape, `Authorization: Bearer ${GATE_API_KEY}`. Never `/v1/messages`.
- `GATE_API_KEY` is server-only. Never print it, log it or send it to the client.
- When the key is missing, every note answers `{ state: "unavailable" }`.
- Free model or nothing: there is no fallback model and no paid route.

**Scope**
- Notes exist for `mainnet` only. Any other `netOf(req)` answers `{ state: "none" }`.
- Unlisted channels get no note (`{ state: "none" }`).

**Rendering the model's text**
- Model text is untrusted. Render it as React text only: no `dangerouslySetInnerHTML`, no markdown rendering.

**Voice and vocabulary** (from `components/aboutCopy.ts`; the voice block in Task 7 carries them)
- Nodes, never machines.
- Snapshots / global snapshots, never ticks; never "L1 snapshots"; never "feeless".
- "Was part of" for a network's share of global snapshots.
- L0 / currency L1 / data L1 are *layers*.
- Geography never mentions decentralisation in any form.
- No causes, no purpose read from numbers, no meta-commentary.
- 2–3 sentences; captions one line.
- No em-dash or spaced en/hyphen clause.

**Honesty (rule 10)**
- Every number in a note or caption must match a fact (Task 1).
- A note that fails is retried once with the failure named.
- A second failure stores nothing and is counted.

**Cache layout**
- Keys are in their own family: `ai:{net}:v{NOTES_VERSION}:{view}:{subject}:{span}`. They never live under `t:` or `geo:`.
- Changing a prompt or a facts shape bumps `NOTES_VERSION`.

**Freshness per note kind** (refresh / TTL)

| Kind | Refresh | TTL |
|---|---|---|
| hyper, geo | 24 h | 72 h |
| ledger | 1 h | 6 h |
| trend `24h` | 1 h | 6 h |
| trend `7d`, `30d`, `1y`, `all` | 24 h | 72 h |
| trend `1h` | on request | 15 min |
| brushed range | on request | 30 days |

**Limits**
- Per visitor (on-request POSTs only): 6 per hour, keyed by the first 16 hex characters of `sha256(ip)`. The raw IP is never stored.
- Global cap: 200 per UTC day. It counts on-request generations plus read-path misses.
- The warmer is not capped; its calls are counted in stats.

**Notable days**
- Only for trend pills `7d`, `30d`, `1y`, `all`.
- Caps: 3, 5, 8, 8 respectively.

**HUD rules**
- Per-view behaviour goes through `VIEW_POLICIES` (convention 7). No `mode ===` checks.
- Every own-server fetch uses `netUrl()` (`src/net/netUrlBoundary.test.ts`).
- No `title=` attribute (`components/tooltipBoundary.test.ts`).
- Gradient tokens are consumed as `[background:var(--x)]`, never `bg-[var(--x)]` (CSS trap 3).
- Colours live in `app/globals.css` tokens with `light-dark()` stops, so both grounds are set at one site.

**Commits**
- Every commit ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- One commit per task, after `npm test` and `npm run typecheck` pass.

## Review Focus

1. **The model is slow, rate-limited (429) or down.** Expect the card to settle on "Notes unavailable — try again later" within the client's give-up window, never an endless "writing…". Tested in Task 8 (generator → `unavailable`) and Task 10 (the hook gives up after its bounded retries).
2. **Two visitors miss the same uncached note at once.** Expect one model call: the second reader gets `pending` and retries. Tested in Task 8 with a fake store whose lock is held.
3. **A subject with nothing measured.** Examples: a network with no snapshots in the span, a network with no node list in Geography, any span before the `geo:` family starts, or a store read that fails. Expect `{ state: "none" }` or present-tense-only facts, never a model call over an empty facts list. Tested in Tasks 3–6: each builder returns `null` when nothing is measured.
4. **A sampler outage inside the span** reads as a node-count crash (`f.nodes` 177 → 32 → 177). Expect no "nodes dropped" fact unless the drop holds at the span's end. Tested in Task 3 (`gaugeChange`).
5. **Odd brushed ranges**: reversed, in the future, wider than the store, under one bucket, or the same brush repeated. Expect a 400 for nonsense, and snapping to whole buckets so a repeat brush hits the same cache entry. Tested in Task 7 (`snapSpan`) and Task 9 (request route).

### Task 2: Notable-day detection

**Files:**
- Create: `src/data/notableDays.ts`, `src/data/notableDays.test.ts`

**Interfaces:**
- Consumes: `NotableDay`, `NotableKind` (Task 1).
- Produces:
  - `notableDays(input: { days: number[]; covered: (number | null)[]; series: Record<string, (number | null)[]>; subject: "dag" | string; ids: readonly string[]; cap: number }): NotableDay[]`. Here `days` are UTC-midnight starts, `covered` is `g.ticks` per day (null = not measured), and `series` holds the daily `m.<id>.snaps`, `m.<id>.gapMax` and `g.anchors` rows.
  - `NOTABLE_CAPS: Record<"7d" | "30d" | "1y" | "all", number>`, equal to `{ "7d": 3, "30d": 5, "1y": 8, all: 8 }`.

**Detection rules** (thresholds are constants in the module; the tests pin the behaviour, not the constants):
- **`high` / `low`:** a covered day whose value is ≥ 2× (high) or ≤ 0.4× (low) the median of the 14 covered days before it. It needs at least 7 such days, and a high value must be ≥ 10. On the DAG the value is `g.anchors`; on a network it is `m.<id>.snaps`.
- **`first`:** the first covered day with `m.<id>.snaps > 0`, only when at least 3 covered days before it read 0 or absent. A network whose activity begins at the start of measuring has no `first`.
- **`last`:** the last day with `snaps > 0`, only when it is followed by ≥ 3 covered days of 0 up to the window's end. A network that resumes loses it.
- **`pause`:** a day whose `m.<id>.gapMax` is ≥ 6× the median of that network's covered `gapMax` and ≥ 3600 s.
- **Whose days:**
  - On the DAG subject: `high`/`low` of the total, plus every network's `first`/`last`.
  - On a network subject: that network's `high`/`low`/`pause`/`first`/`last`.
- **Ranking:** by `score`, which is `|log(value/level)|`; `first`/`last` score `+Infinity`. Then cap.

- [ ] **Step 1: Write the failing tests:**
  - a 30-day flat series of 100 with day 20 = 250 yields exactly one `high` on day 20
  - an uncovered (null) day of 0 yields nothing (an outage is not a low)
  - a network at 0 for days 0–9, then active, yields `first` on day 10
  - the same network active from day 0 yields no `first`
  - activity ending on day 25 of 30 yields `last` on day 25
  - activity ending on day 28 of 30 (only 2 quiet days) yields nothing
  - 12 candidate highs with cap 5 yield 5, sorted by score
  - the same input twice yields deep-equal output
  - `NOTABLE_CAPS` equals the map above

- [ ] **Step 3: Implement** `notableDays` and `NOTABLE_CAPS` per the rules above.

  8. **Store:** `set(key, JSON(record), ttlS)`, then stats `ok`, then `unlock`. Always unlock in a `finally`.
  9. **Read misses:** before calling the model in `read` mode, `incr(capKeyOf)` > 200 → `unavailable`, with stats `capped`.
