D — Signers tab

Today: two groups ("Data, signed by dL1" and "Snapshot (state & data), signed by L0"), each a two-column table, Node and Signer id. The same three nodes usually appear in both groups, and the signer id is the node id's first 8 characters, so most of the tab says the same thing four times.

Two earlier rulings hold: a signature belongs to a node (its id, never its city), and the signer id exists to show when a hybrid node signs with a different key. So the column goes only where it repeats the node id.

D1 One roster, a column per layer recommended

  • One row per node that signed anything; two narrow columns, dL1 (the data) and L0 (the snapshot), with a check where that node signed. "Who signed what" reads at a glance, and a node that signed only one layer shows a dash in the other.
  • The node id keeps its copy control. The signer id is gone from the row unless it differs from the node id; then it shows as a second line, "signed as 1a2b3c4d" (the hybrid case the column was for).
  • One check style only, no colour key: the column heads are the key.
  • Paging by three (one quorum) stays for chains with more signers.

D2 Two groups, folded when equal

  • Keeps today's two groups, but each is a plain list of node ids (no Signer id column unless it differs, as in D1).
  • When both layers were signed by the same nodes, the groups fold into one with a sentence head: "Data and snapshot, signed by the same 3 nodes".
  • Closer to today, but a reader has to compare two lists by eye whenever they differ.
