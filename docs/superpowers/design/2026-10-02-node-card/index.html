Node card — four ways to lay it out

The node card is the one card that is a record of a single thing, so it has no breakdown to lead with: today it is a lead sentence and five plain rows. Each option below is drawn twice, for the two kinds of node the card has to serve: a DAG validator with every fact filled in, and a metagraph data node where several facts are empty.

All four keep the agreed pieces: id as the title, status pill in the head, one lead sentence, the foot with the node id, the pager, one dash for an empty value. Figures are illustrative. Nothing here is built except A.

Recommend C. A node's two real questions are "what does it run" and "how much of the chain does it keep", and C answers both as pictures at the top of the card (three layer cells, one archive bar) and leaves the look-up facts as plain rows underneath. It also shows what a node does not run, which the chips in A and B cannot. B is the safest change if you only want the card tidier. D makes the archive the hero, which over-serves one fact on cards where it is empty.
Your call (a) Which layout. (b) Whether an empty row stays as a dash (as agreed for every card) or is left out on this card, since a data node can have three dashes in a row. (c) Whether "Delegated staking" stays a row or becomes a chip beside the status pill.
